# 周期报告、观察与数据恢复

## 周报 / 月报

选择「本周 / 本月」和定位日期，点击「预览新报告」，检查后保存。周按上海时区的周一至周日，月按自然月。生成方式为**本地确定性规则，不调用 AI**。

保存后是一份不可变历史快照。后续修改内容、指标或观察，不会重写旧报告；同一周期可以重新生成另一份快照。历史下拉框用于选择，复制和下载都读取所选快照的 Markdown。

数字缺失显示未知而非零。周期不匹配、账号与作品口径、重叠快照等限制会在数据缺口中列出；不能把已知小计当完整平台总量。

## 热点 / 竞品观察

人工录入或由后续 WorkBuddy API 提交，保留来源链接、平台、摘要与值得记录的理由。0–100 的热度为人工评分，并非抓取的平台热度。

「收入灵感」先确认再提交，事务内创建灵感并保留原始来源。重试不会重复创建；已转化的观察不能抹去转化历史。忽略的观察要先恢复为待判断，才能转化。本应用不会自动联网搜索或登录平台。

## 设置

关键词和四平台展示配置保存到本地数据库。账号仅为展示名称与主页链接，不保存密码。WorkBuddy「本地 Token 已配置」只说明服务端凭据存在；「最近已认证请求」才是实际 API 请求记录，也不等于 WorkBuddy 进程在线。

## 备份和恢复

1. 设置页点击「立即备份」，等待成功提示。备份包含一致性 SQLite 副本与 JSON 清单（版本、时间、Schema、大小、SHA-256）。
2. 定期把 `data/backups/` 中数据库及同名清单**一起**复制到独立安全位置。只留在同一磁盘不能防硬盘损坏。
3. 恢复时先选择备份并核验。损坏、路径异常或不兼容备份不能恢复；备份目录的异常记录会显示警告。
4. 核对时间和校验和，勾选确认并输入「恢复」，再点击「确认恢复」。取消不会替换当前数据，确认票据五分钟后失效。
5. 服务暂时阻止新 API 请求并等待已接收请求完成，先备份当前数据，再恢复、重新绑定数据库连接并检查健康状态。原 Token 文件不被替换。
6. 成功后重新加载设置，确认业务数据。失败时服务尝试恢复原数据库；若磁盘故障导致回滚也无法完成，保持维护状态，停止写入并检查磁盘/备份，不要盲目重复恢复。

备份与恢复使用数据库外的幂等收据；不确定中断不会自动重复执行危险操作。出现「前次操作未完成」时，先检查当前数据及健康状态，再重新核验。完整掉电/硬盘损坏无法由软件保证恢复。

当前保守保留备份，不自动删除历史文件；注意磁盘空间，人工清理前先验证独立副本。不要用文件管理器覆盖正在运行的 SQLite 文件。旧版本兼容备份在临时副本中迁移后才替换当前库；未来版本或迁移校验和不符会被拒绝。

本阶段所有自动化演练均使用操作系统临时目录中的虚构数据，没有写入老板真实 `data/`。
