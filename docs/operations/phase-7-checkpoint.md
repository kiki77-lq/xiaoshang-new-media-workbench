## 实现

- WorkBuddy仓库内Skill和API-only客户端，记/找/改/看、四平台与跨实体查询；本机Bearer、稳定请求键、版本锁、原话不可改、失败不宣称成功。
- 普通业务POST幂等24小时；超期或时间未知先查，PATCH按版本核对，不假定POST式回放。独立Skill场景验证发现时效缺口后已修正。
- 安装、重复安装、启动/停止/状态；Node24、SQLite迁移、本地凭据、受控后台进程、健康核验。
- 更新前排空在途请求和核验备份；只拉取检查过的快进SHA；候选进程验收前不开放业务；失败回退旧代码与数据库并保留Token、非数据库文件及Git历史。
- 中断日志与显式恢复，锁不自动抢占；开放写入后的不确定更新只向前恢复，避免覆盖新增数据。
- 候选 Git 忽略规则在停服前隔离验证，不能让运行数据失去保护；恢复请求即使客户端断开也要等服务端操作完成才能停服。
- 独立 SQLite 进程租约覆盖 prepare、服务、更新停服及回滚窗口；同库不同端口不能重复启动，业务 DB 的恢复/rebind 不释放租约，进程退出由 OS 释放占用。
- 中文README、上游归属和历史文档提示；手机快速新增按钮高度回归修复，PWA静态外壳v8、API不缓存。
- 灵感展示真实 WorkBuddy 来源及上海时间，不依赖电脑时区。

## 交付边界

实际老板电脑、实际WorkBuddy进程、Windows、开机自启、公网/LAN手机访问未验收。已验证的是本机独立临时克隆与真实Node/SQLite/浏览器/CLI。

同库排他保护限于遵守当前协议的启动入口与本机磁盘；外部数据库工具、旧版程序和网络共享文件系统不在保证范围。不能删除 process-lease.sqlite 解除占用。

备份与操作收据保守保留，需人工注意容量并异盘备份。断电、陈旧锁、双重磁盘故障可能需人工核验精确路径后恢复；脚本不自动清锁。若候选代码损坏恢复CLI且进程中断，需要维护者先恢复可执行旧代码。Node SQLite实验提示与终端颜色变量警告不属于浏览器错误。

V1不包含微信、爬虫、平台官方API、自动发布、外部AI调用、多IP、素材库或V2功能。
